Как выпустить новую версию MathBoard
====================================

Коротко: поднять версию в MathBoard.csproj -> закоммитить и запушить -> создать и запушить тег vX.Y.Z.
GitHub сам соберёт установщик и выложит релиз, а установленные программы увидят обновление при следующем запуске.


1. Один раз перед первым релизом
--------------------------------
- Репозиторий github.com/VortexSo4/MathBaord должен быть публичным: программа проверяет обновления без логина.
  Если сделать его приватным, автообновление перестанет видеть релизы.
- Папка .github/workflows (файл release.yml) должна быть закоммичена и запушена — без неё GitHub ничего не соберёт.
- На GitHub: Settings -> Actions -> General -> "Allow all actions" (обычно включено по умолчанию).
  Права на создание релиза выдаются в самом release.yml (permissions: contents: write), отдельно настраивать не нужно.
- Первую установку на каждый компьютер делаете вручную установщиком (MathBoard-X.Y.Z-setup.exe из релиза).
  Обновляется только версия, поставленная установщиком; копия, запущенная из папки сборки, не заменится.


2. Каждый релиз
---------------
1) Поднимите версию в MathBoard/MathBoard.csproj:
       <Version>1.2.0</Version>
   Версия должна быть больше предыдущей (сравниваются числа: 1.10.0 > 1.9.0).

2) Закоммитьте и запушьте изменения:
       git add -A
       git commit -m "Версия 1.2.0"
       git push

3) Создайте тег — буква v и та же версия — и запушьте его:
       git tag v1.2.0
       git push origin v1.2.0

4) Откройте на GitHub вкладку Actions: там запустится "release" (около 5 минут).
   Когда он станет зелёным, во вкладке Releases появится "MathBoard v1.2.0" с файлом MathBoard-1.2.0-setup.exe.

5) Всё. При следующем запуске программа покажет точку на кнопке меню и на "Настройках";
   в настройках строка "Версия ..." -> "Установить 1.2.0". После нажатия программа сохранит доску, закроется,
   тихо установит новую версию и запустится снова.


3. Правила, которые нельзя нарушать
-----------------------------------
- Тег = "v" + <Version> из csproj. Если они не совпадут, сборка на GitHub остановится с ошибкой
  "Tag ... does not match version ...".
- Файл в релизе должен называться ровно MathBoard-<версия>-setup.exe — программа скачивает его по этому имени.
  Сборка называет его так сама; при ручной загрузке не переименовывайте.
- Программа смотрит только на "последний" релиз (Latest). Черновики (Draft) и пре-релизы (Pre-release) она
  не видит — ими удобно проверять сборку, не раздавая её всем.
- Не удаляйте старые теги и релизы без нужды: ссылки на них никому не мешают.


4. Если что-то пошло не так
---------------------------
- Сборка в Actions красная: откройте её, посмотрите шаг с ошибкой, исправьте код и выпустите тег заново:
       git tag -d v1.2.0
       git push origin :refs/tags/v1.2.0
   (если релиз всё же успел создаться — удалите его на странице Releases), затем снова шаги 2–3.
- Забыли поднять версию в csproj: удалите тег как выше, поднимите версию, закоммитьте и создайте тег заново.
- Программа не видит обновление: проверьте, что релиз не Draft/Pre-release, что версия в нём больше установленной,
  что в настройках включено "Проверять обновления при запуске" (или нажмите "Проверить"). Подробности — в логе
  (Настройки -> Открыть последний лог), строки "Update ...".


5. Собрать установщик у себя (без GitHub)
-----------------------------------------
Нужны .NET 9 SDK и Inno Setup 6. В PowerShell из корня репозитория:
       .\scripts\build-installer.ps1
Готовый файл: installer\MathBoard-<версия>-setup.exe (папки publish и installer в git не попадают).
Его можно выложить в релиз вручную: Releases -> Draft a new release -> тег v<версия> -> приложить exe -> Publish.
